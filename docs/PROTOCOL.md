# automation-ir v1

Status: G2 protocol and validation baseline. Protocol 3 is not yet connected to DND-card-web. G1 candidate counts are not automation coverage.

The envelope contains `schemaVersion: 1`, `protocol: 3`, a complete `versionLock` and unique `records`. JSON Schema 2020-12 rejects unknown fields. Validation is pure: no network, file mutation or arbitrary script execution. `src/validate/index.ts` returns issue codes and paths without echoing rejected prose.

## Identity and references

`src/identity.ts` is the shared browser-safe codec. It normalizes Unicode using NFKC, trims/collapses whitespace, lowercases each key component, percent-encodes it and joins components with colons. Order: packId (default kiwee), kind, source, English name, class source/name, subclass source/short name, feature level, race source/name, extra. Source fields are uppercase in the record. Parent source/name pairs must be complete. No translated parent names or guessed English identifiers are accepted.

2014 and 2024 core sources remain separate. Explicit editions on extension-book records also participate in reference checks. `entryIds` are secondary compatibility links and never replace the canonical identity. Unresolved G1 identifiers are inventory diagnostics, not accepted G2 identities. A declarative alias with source evidence is needed before publishing those rows.

## Records

| Field | Meaning |
| --- | --- |
| identity | Canonical identity fields and matching key |
| edition | 2014, 2024, or both for eligible extension content |
| entryIds | Optional secondary card catalogue IDs |
| verdict | automated, noMechanics, needsAnnotation, unsupported |
| provenance | Nonempty list: structured, foundry, overlay, rulePack, inventory |
| evidence | Page and optional quote of at most 15 words |
| mechanics | Modifiers, grants, resources, actions, deferred effects and typed models |
| unsupported | Mechanism family, reason code, optional reference/deferred marker |
| reasonCode | Required for noMechanics; bounded enum |
| autoGenerated | Must be true for needsAnnotation; overlays cannot use that verdict |
| notes | Private annotation only; removed by publicArtifact before publication |

`automated` requires operative mechanisms and no unsupported families. Deferred effects or combat settlement actions cannot qualify. `noMechanics` needs narrative, placeholder, choiceOfOtherEntry, coveredByParent, tableOnly or asiPlaceholder, and cannot also contain operative or unimplemented mechanisms. `unsupported` requires an identified family/reason. `needsAnnotation` is a generated diagnostic, never a contributor shortcut.

## Mechanisms

Modifiers have a whitelisted target, add/set/min/max/upgrade operation, and exactly one literal value or formula. Conditions use structured all/any/not predicates. Grants specify fixed choices or a count and a finite list/filter; ability-score weighting is explicit. Spell grants and cast actions reference this version's spell catalogue. Spell filters must match actual catalogue entries and cannot cross editions.

Resources have a stable key, maximum, recovery definitions and optional ascending level scaling. Recovery periods are short/long/dawn/manual; amount is all, an integer from 0 to 10000, or a parsed formula. Duplicate normalized keys or periods are rejected. Actions consume a declared resource. This data describes an operation; deferred combat/duration semantics remain visible rather than being counted as executed.

Class models carry typed hit dice, casting progressions, slots and feature references. Equipment models carry numeric armor/weapon and attunement data. Spell models identify spell level, school, ritual/concentration flags and English class identities; their presence alone does not establish full spell automation. Foundry scale definitions are explicit level tables.

## Formulas

The parser supports arithmetic, parentheses, literal dice, floor/ceil/min/max, and these variables: `@class.level`, `@classes.<id>.levels`, `@details.level`, `@prof`, `@abilities.<ability>.mod`, `@scale.<id>`. Scale identifiers use letters, numbers and underscores, with optional dotted components; hyphen is reserved for subtraction. Class IDs may include hyphens before the `.levels` terminator.

Token count, nesting, literals and dice sizes are bounded. Numeric evaluation requires supplied finite variable values, rejects dice without an explicit roll, division by zero and nonfinite/out-of-bounds results. No eval, JavaScript functions, actor fields or script fragments are supported.

## Overlays and version lock

Each overlay needs a reviewer, valid review date, batch and page evidence. Overriding structured/Foundry derivation additionally needs `overrides` and `overrideReason`. Canonical identity keys cannot repeat in an overlay file. Final overlay provenance preserves the review evidence.

The lock includes changelog version/date, fetchedAt, Foundry migration versions, tool version and each HTTPS input's namespace/path/role/byte count/SHA-256. Validation detects missing and duplicate inputs. Fetch/replay additionally verifies actual file hashes; an asserted hash in an imported JSON document is not proof of its provenance.

## Validation evidence

`test/validator.vitest.ts` exercises all eleven execution-plan invariants with positive and negative cases, plus canonical-key integrity, explicit verdict restrictions, overlay reversals, quote limits and privacy of errors. The appendix E examples are structural schema fixtures. Second Wind's healing settlement is deferred in this scope, so its complete-automation verdict from the illustrative document is rejected by semantic validation; a partial unsupported verdict is required for a publishable artifact. This distinction keeps schema examples from inflating coverage.
