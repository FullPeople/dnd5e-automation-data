# Attuned charge bookkeeping observer — draft source checkpoint

The observer now characterizes source-verified literal-attunement routes using
the consumer's real acquisition/debit APIs. It first verifies rejection with
missing marks, then supplies explicit disposable equipped/attuned context and
observes a known balance of two decrease to one. Loss of a current mark is
checked again. No real character data or source prose is included.

The existing version-one `item-charge-accounting` witness schema is unchanged.
Previous consumer gates are retained, including manual/native data, duplicate,
resource-lock, permission, revocation and no-refill protections. Exact attuned
and closed-normalization evidence modules are added to the source binding.

Local focused tests: 28 new checks passed; 69 prior item/contract checks passed
separately, zero skipped. Nine missing/wrong-input controls fail closed. These
are source-checkpoint results, not a completed full-catalog replay or browser
acceptance. The existing report remains historical until an exact new replay
and consumer pairing replace it.

The consumer's 128 supported routes are partial fixed-one-charge bookkeeping,
not whole-item completion. Effects, spells, recovery, terminal consequences and
attunement procedure, eligibility and slot limits remain manual or held.
This independent draft checkpoint is not merged or deployed.
