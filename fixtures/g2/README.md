## E1: Second Wind PHB

Fixture: `e1-second-wind-phb.json`.
Original row: `data/class/class-fighter.json#/classFeature/1`,
`ENG_name: Second Wind`, source PHB, level 1, page 72; English-name line 2052.
Parent: `data/class/class-fighter.json#/class/0`, `ENG_name: Fighter`,
source PHB; English-name line 9. The parent row resolves the translated
`className` into `classEngName: Fighter`.

**Missing real mechanism shape:** the PHB row has no structured resource or
healing fields. Its retained subset is identity, parent, level, source, and page
metadata only. `data/class/foundry.json#/classFeature/88` has
`ENG_name: Second Wind` (line 4445), but source XPHB; there is no matching PHB
Foundry row. That XPHB row is diagnostic evidence only and is not used by E1.
No PHB Foundry provenance, migration version, or raw healing subset is invented.

The complete resource (max formula `1`; short/long recovery `all`), bonus/self
healing formula `1d10 + @class.level`, and consumption of one `second-wind`
use come from the authorized section 4.4 example. Healing is explicitly
`deferred: true`. Page 72 is real metadata, not proof of extracted mechanics.

**Schema/validator distinction:** E1 retains the document's `automated` verdict
only as a schema-positive example. The schema permits the deferred action;
the semantic validator rejects this record with `deferred`. Actual healing
execution is deferred, so E1 must not count as full automation or enter a
validated public artifact. This missing PHB shape remains a limitation.

## E3: Magic Initiate Cleric XPHB

Fixture: `e3-magic-initiate-cleric-xphb.json`.
Original parent: `data/feats.json#/feat/176`, `ENG_name: Magic Initiate`,
source XPHB, page 201; English-name line 9003.
Actual variant: `data/feats.json#/feat/176/_versions/0`,
`ENG_name: Magic Initiate; Cleric`, source XPHB; English-name line 9141.
Page 201 is inherited from the parent. The identity preserves this actual
semicolon spelling rather than the appendix's parenthesized display label.
Class resolver: `data/class/class-cleric.json#/class/1`,
`ENG_name: Cleric`, source XPHB; English-name line 522.

Retained subset: variant `additionalSpells[0]` only.
`known._[0].count: 2` and its level-0 class filter become the free cantrip grant;
`innate._.daily["1"][0]` and its level-1 class filter become one level-1 choice.
An omitted choose count means one. Translated class tokens resolve through the
real XPHB Cleric row, producing structured English filters with
`classSource: XPHB`. `ability.choose: [int, wis, cha]` applies to both grants.

Limit: the raw `daily["1"]` encodes a frequency of one, but does not itself
encode long-rest recovery or spell-slot eligibility. The long/all recovery and
`slotOrUses` usage follow Appendix E3, with explicit specification provenance;
they are not claimed as additional raw fields. Repeated ability choices denote
one shared ability selection; this schema has no shared-choice identifier.
Repeatability, spell replacement, and runtime spell resolution are outside the
subset. No spell choices are preselected; semantic validation needs a real
2024 Cleric spell catalogue matching both filters.
